# ツール選択の評価

**測るのは「呼ばれれば正しく答えるか」ではなく「呼ばれるか」。**

`mcp/test/smoke.mjs` は `callTool('judge_worker_type', {...})` の形で、名前を指定して
呼んでいる。動くことは確かめられるが、**利用者は名前を打たない。**「パートさんも社会
保険入るんですか」と聞くだけで、そこから正しいツールに辿り着けるかは別の問題になる。

ここはそれを測る。

## 何を比べるか

同じツール一覧と質問を与え、**サーバーの案内文だけを差し替えて**2回走らせる。
差が出れば案内文が効いている。出なければ効いていない。

判定はモデルの判断なので、スイートに組み込んで毎回自動で走らせることはしていない。
ツールを足したとき、説明を書き換えたとき、案内文をいじったときに手で回す。

## 使い方

```
python mcp/eval/build.py          # 素材を組み立てる (tools.json / prompt_*.txt)
```

出来上がった `prompt_*.txt` を、それぞれ別のモデルに渡す。渡すのは案内文とツール
一覧と質問だけで、**正解は渡さない**。26問(または18問)の「番号 ツール名」を
返させ、`score.py` に食わせる。

```
python mcp/eval/score.py answers_a.txt answers_b.txt
```

## 質問の作り方

**案内文やツール説明にある言い回しをそのまま使わない。** 同じ文字列を入れれば文字列
照合を測ることになり、意味で選べるかは分からない。

`questions.json` は日常語の26問、`questions_hard.json` は数値と表を含む18問。
後者には次を混ぜてある。

- 表を貼られたときに単発ではなくバッチを選ぶか (Q2, Q10)
- 制度名が一切出ない質問から辿れるか (Q14 は生年月日だけが手がかり)
- 似た制度の取り違え — 退職月の賞与は資格判定が先 (Q12)、育休復帰は随時改定ではなく
  休業終了時改定 (Q17)、4〜6月が突出するなら年間平均 (Q13)

## これまでの結果

### 2026-08-27 — 口語→ツールの対応表を案内文に足して測った

| セット | routing あり | routing なし | 差 |
|---|---|---|---|
| 日常語 26問 | 26 / 26 | 26 / 26 | **0** |
| 数値と表 18問 | 18 / 18 | 18 / 18 | **0** |

**44問すべてで回答が1問残らず一致した。**対応表は選択に何も足していない。

理由は説明がつく。26本の説明はいずれも200字以上あり、本文に「いつ呼ぶか」が書いて
ある。タイトルが制度名でも、説明を読めば分かる状態だった。対応表はそこに重ねただけ
だった。約1,105トークンを毎セッション払うだけなので外した。

MCP 仕様上 `instructions` は "Optional instructions for the client" で、クライアントが
どう使うかは規定されていない。この実験は「そのまま読まれる」という最良の前提で走らせて
なお差が出なかったので、実際にはさらに弱いと考えるべき。

**両方が満点なので、上限に張り付いて差を検出できていない可能性は残る。**ツールが増えて
選択が難しくなったときには、同じ質問で差が出るかもしれない。そのときのために手順を
残してある。

## 次にこれを回すとき

ツール数が増えたときが本番になる。公開されている調査では、絞ったツールセットで95%
だった選択精度が、大きなMCPを丸ごと読み込むと71%まで落ちている。劣化が始まるのは
概ね30〜50本という指摘が複数ある。

`mcp/test/smoke.mjs` に上限30の検査を置いた。超えたときにすべきは検査を緩めることでは
なく、まずここで測ること。落ちていなければ緩めてよいし、落ちていれば統合を考える。
