日本の給与計算に必要な数字を、ひとつのAPIにまとめました。
AIアシスタントから使う **MCPサーバ**と、プログラムから叩く **HTTP API** の2つです。
どちらも無料枠があり、鍵なしで試せます。

```bash
npx jp-payroll-mcp
```

```bash
curl "https://japan-payroll-api.tsumugi.workers.dev/v1/payroll?prefecture=Tokyo&monthly_salary=300000&age=40"
```

1回の呼び出しで、健康保険・介護保険・厚生年金・子ども子育て拠出金・雇用保険・
源泉所得税・手取り・事業主負担が返ります。

- MCPツール **28本** / HTTPエンドポイント **43本**
- 47都道府県の料率、源泉徴収税額表、割増賃金、年次有給休暇、標準報酬月額の決定と改定、
  産休育休の免除、最低賃金(24年分)、消費税率、祝日と営業日計算、法人番号の検査
- **答えには必ず根拠の条文が付きます**
- GitHub: https://github.com/kishida-devil/jp-payroll-mcp

## なぜ作ったか — 自前で書くと外れる5か所

給与計算のデータは公開されています。それなのに正しく出すのが難しいのは、
**ふつうに書けばふつうに間違える場所**がいくつもあるからです。

どれも例外的な事例ではなく、毎月起きる普通の処理です。しかも**間違えても計算は完走し、
それらしい数字が出る**ので、指摘されるまで気づきません。

以下の数値はすべてこのAPIに実際に計算させた結果で、記憶から書いたものはありません。

### 1. 退職日が1日ちがうと、1か月分の保険料が動く

同じ3月に退職した2人で比べます。東京都・40歳・月給30万円。

| 退職日 | 資格喪失日 | 3月分の社会保険料 |
|---|---|---|
| 3月30日 | 3月31日 | **かからない** |
| 3月31日 | 4月1日 | **かかる** |

労使合計で **95,130円**(従業員 46,500円・事業主 48,630円)の差です。1日の違いで。

理由は2つの条文の組み合わせです。

- **健康保険法第36条** — 資格喪失は**退職日の翌日**
- **健康保険法第156条第3項** — **資格喪失月**の保険料は算定しない

3月30日退職なら喪失日は3月31日で、3月が喪失月になるので3月分はかかりません。
3月31日退職なら喪失日は4月1日で、喪失月は4月。**3月は在籍月なので満額かかります。**

「月末に辞めると1か月分多く引かれる」という現場の言い伝えは、正確にはこれです。

**ありがちな実装:** 退職日の属する月を喪失月として扱う。3月31日退職を「3月で喪失」と
読むと、1か月分の保険料が消えます。

```bash
curl "https://japan-payroll-api.tsumugi.workers.dev/v1/eligibility?month=2026-03&left_on=2026-03-31"
```

### 2. 年齢は誕生日の前日に上がる

**4月1日生まれの人の介護保険料は、3月から引きます。**

1986年4月1日生まれで計算させると、こうなります。

```
40歳 到達日: 2026-03-31
適用開始月: 2026-03
```

誕生日は4月1日なのに、40歳に達するのは**3月31日**です。
根拠は **年齢計算ニ関スル法律**(明治35年法律第50号)で、年齢は誕生日の前日に加算されます。

介護保険料は「40歳に達した日の属する月」から発生する(**介護保険法第9条第2号**)ので、
3月分から徴収が始まります。**4月から、ではありません。**

同じことが65歳・70歳・75歳の節目でも起きます。
1日生まれの人だけ、すべての区分が1か月早く動きます。

**ありがちな実装:** `birthday.month === now.month` で判定する。1日生まれが全部1か月ずれます。

### 3. 「2等級差」は健康保険法に書いていない

随時改定(月額変更届)の要否を決める「2等級以上の差」という条件。
**健康保険法を最後まで読んでも出てきません。**

出典は **昭和36年 保発第4号** という通達です。

判定させると、できない理由まで返します。

```json
{
  "applies": false,
  "blocking_reasons": [
    "健康保険・厚生年金保険のいずれも等級差が2に届きません。上限・下限付近の例外にも該当しません (保発第4号 記2(1))。"
  ]
}
```

さらに厄介なのは、**1等級差でも改定が必要になる例外が4つある**ことです。
等級表の上限・下限付近では、2等級動きようがないためです。

「法律に書いてあるはず」と思って条文だけを追うと、この規則には辿り着けません。
**日本の労務は、法律・政令・省令・通達の4層で決まります。**通達を無視すると外れます。

### 4. 保険料は標準報酬月額、雇用保険は実際の賃金

同じ給与明細の中で、**課税標準が2種類**あります。

| 保険 | 何にかかるか |
|---|---|
| 健康保険・介護保険・厚生年金 | **標準報酬月額**(50等級の階段) |
| 雇用保険 | **実際に支払った賃金** |

残業して給与が増えた月、雇用保険料は増えますが、社会保険料は**等級が変わらない限り増えません**。
標準報酬月額は年1回の定時決定(4〜6月の平均)で決まり、大きく動いたときだけ随時改定が入ります。

端数処理も違います。社会保険料の従業員負担分は、**0.50円以下は切り捨て、0.50円を超えると切り上げ**
(昭和22年11月14日 保険発第179号)。四捨五入ではありません。

**ありがちな実装:** 総支給額に料率を掛ける。等級の階段を無視すると、多くの月で数百円ずれます。

### 5. 最低賃金は「毎年10月」とは限らない

地域別最低賃金は毎年10月に改定される、と説明されます。だいたい合っていますが、
**発効日は都道府県ごとに違います。**

令和7年度の秋田県を引くとこうです。

```
fiscal_year: 2025
hourly_wage: 1031
effective_from: 2026-03-31
```

**2026年3月31日発効。**「10月に一律で切り替わる」と実装すると、
**半年近く違う額を使い続けます。**

最低賃金法第4条は、最低賃金額に達しない賃金を定める労働契約をその部分について**無効**とし、
最低賃金と同様の定めをしたものとみなします。古い額で「適法」と表示することの意味は、
単なる表示の誤りでは済みません。

## 答えには根拠の条文が付きます

条文名を挙げて「あとは自分で探してください」では半分の答えです。
健康保険法・厚生年金保険法・徴収法など8法令の条項を同梱してあるので、その範囲は同じ呼び出しで**実際の文言**にできます。労働基準法や所得税法のように同梱していない法令は、**推測した本文を返さずに断り、e-Gov の該当条文へ案内します。**

```bash
# 条文そのもの
curl "https://japan-payroll-api.tsumugi.workers.dev/v1/statute?ref=健康保険法第43条"

# 判定が引用したものを、その答えに添える
curl "https://.../v1/standard-remuneration/revision?...&include=statute_text"
```

実務で書かれる略称もすべて解決します(健保法43条、厚年法81条の2、徴収法11条)。
e-Gov の公式略称は「厚生年金法」ですが実務では「厚年法」と書くので、**両方通ります。**

## 数字の出どころ

すべて公式資料から機械的に抽出し、**そこに印刷されている値と突き合わせて**います。
式の説明から書き直したものではありません。

| データ | 出典 |
|---|---|
| 社会保険料率・等級表 | 全国健康保険協会 保険料額表 |
| 源泉徴収税額表 | 国税庁 源泉徴収税額表 |
| 最低賃金 | 厚生労働省 地域別最低賃金 |
| 祝日 | 内閣府 |
| 改定の規則 | e-Gov 法令検索、日本年金機構 |

協会けんぽの保険料額表と**250通り(5都道府県×50等級)**、国税庁の月額表の**公表2,079セル全部**を
照合しています。変更のたびに全件を実行します。

`/v1/data-freshness` が各データの収録範囲と次の改定時期を返すので、
**古くなったことが黙って進行しません。**収録範囲の外の日付は、古い数字を返さずに断ります。

## 自分で確かめるには

上に挙げた条文は、**e-Gov 法令API** で本文を取得できます。

```bash
curl "https://laws.e-gov.go.jp/api/2/law_data/大正十一年法律第七十号?law_full_text_format=json&elm=Article_36"
```

健康保険法は「大正十一年法律第七十号」です。`elm` に条番号を渡すとその条だけ返ります。
**通達(保発第4号など)は法令ではないので、ここには入っていません。**
厚生労働省の通知検索や日本年金機構の資料に当たる必要があります。

「法令APIに無い = 存在しない」ではない、というのがこの領域の難しさです。

## 使い方

**MCPサーバ**(Claude Desktop / Claude Code から):

```bash
claude mcp add jp-payroll -- npx -y jp-payroll-mcp
```

「3月31日に辞めた人の社会保険料は?」と日本語で聞けば、上の判定を計算して
**根拠の条文を添えて**返します。無料・鍵不要です。

**HTTP API**(ソフトウェアに組み込む):

無料枠は鍵なしで使えます。回数の上限はなく、違いはバッチの人数だけです
(無料は1回10人まで)。500人を1回で処理する必要が出たら
[RapidAPI](https://rapidapi.com/kishidadevil/api/japan-payroll-and-labor-constants) の
有料プランへ。OpenAPI 3.0 の仕様書を配信しているので、クライアントは自動生成できます。

## 正直に書いておくこと

- **届出の要否を判定するものであって、届出ではありません。**保険者算定は日本年金機構の
  判断で異なることがあり、APIから見えない事実で決まる論点もあります
  (差が「例年発生することが見込まれる」かどうか、支給が実費弁償に当たるかどうか)。
- **住民税は算出しません。**前年所得と市区町村で決まり、事業主が計算するものではありません。
- **国民健康保険の額も返しません。**市町村の条例で決まるため、全国一律の額が存在しません。
  「無い」ことを理由つきで返します。
- **年末調整は対象外です。**
- **政府機関の承認・関与・保証を受けたものではありません。**法定の届出に用いる前に、
  出典と照合してください。

間違いを見つけたら [GitHub](https://github.com/kishida-devil/jp-payroll-mcp) に issue を
ください。条文の読み違いが一番ありがたいです。
