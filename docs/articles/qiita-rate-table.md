# 協会けんぽの保険料額表を、自前で持たずにJSONで引く

給与計算を実装すると、最初に詰まるのがデータです。ロジックではありません。
**47都道府県 × 50等級の表を、どこから持ってきて、どう保守するか。**

私はこれをAPIにしました。この記事は、その中で分かった「表そのものが持っている罠」の話です。
自分で作る人にも使える内容にしてあります。

```bash
curl "https://japan-payroll-api.tsumugi.workers.dev/v1/standard-remuneration/table"
```

数字はすべてこのAPIに実際に返させた結果で、記憶から書いたものはありません。

## 1. 等級表は1つではない。健康保険50・厚生年金32

いちばん多い間違いがこれです。等級表を1枚のテーブルとして持つと外れます。

| | 等級数 | 標準報酬月額の範囲 |
|---|---|---|
| 健康保険 | **50** | 58,000円 〜 1,390,000円 |
| 厚生年金 | **32** | 88,000円 〜 650,000円 |

しかも**ずれ方が上下で非対称**です。厚生年金の1等級は健康保険の4等級に対応し、
厚生年金の32等級は健康保険の35等級に対応します。

- 健康保険にしか無い等級: **下に3つ、上に15つ**
- 月給70万円の人は、健康保険では44等級、厚生年金では**32等級で頭打ち**

`pension_grade` が `null` の行が18行あるのは、そういう意味です。

```json
{"health_grade": 4,  "pension_grade": 1,    "standard_monthly_remuneration": 88000,  "remuneration_from": 83000,   "remuneration_to": 93000}
{"health_grade": 35, "pension_grade": 32,   "standard_monthly_remuneration": 650000, "remuneration_from": 635000,  "remuneration_to": 665000}
{"health_grade": 50, "pension_grade": null, "standard_monthly_remuneration": 1390000,"remuneration_from": 1355000, "remuneration_to": null}
```

**上限・下限は開いています。**1等級の `remuneration_from` と50等級の `remuneration_to` は
`null` です。ここを 0 や 9999999 で埋めると、境界の比較でずれます。

## 2. 料率は都道府県ごとに違う。しかも41通りある

健康保険料率は都道府県ごとです。「47個の値がある」と思って配列を用意すると、
**実際に異なる値は41通り**でした(同率の県があるため)。

令和8年度の実測値です。

| | 都道府県 | 料率 |
|---|---|---|
| 最安 | 新潟 | **9.21%** |
| | 沖縄 | 9.44% |
| | 福島 | 9.50% |
| 最高 | 徳島 | 10.24% |
| | 北海道 | 10.28% |
| | 佐賀 | **10.55%** |

差は **1.34ポイント**。月給30万円の本人負担で言うと、新潟 13,815円 / 佐賀 15,825円 —
**年間 24,119円** 違います。「だいたい10%」で実装すると、この幅を全部間違えます。

一方で、**都道府県で変わらないもの**もあります。ここを一緒に扱うと保守が壊れます。

| 項目 | 令和8年度 | 都道府県別か |
|---|---|---|
| 健康保険 | 9.21〜10.55% | **はい** |
| 介護保険(40〜64歳) | 1.62% | いいえ(全国一律) |
| 厚生年金 | 18.30% | いいえ |
| 子ども・子育て拠出金 | 0.36% | いいえ(**全額事業主**) |

```bash
curl "https://japan-payroll-api.tsumugi.workers.dev/v1/insurance-rates?prefecture=Niigata"
```

## 3. 端数は四捨五入ではない

被保険者負担分の端数は **五捨六入** です。
0.50円**以下は切り捨て**、0.50円を**超えると切り上げ**。

根拠は昭和22年11月14日 保険発第179号。`Math.round()` を使うと、0.50円ちょうどの
ケースだけ1円ずれます。50等級 × 47都道府県 × 2軸(介護あり/なし)の中には、
必ずそこに当たる組み合わせがあります。

## 4. 表は毎年3月分から変わる

令和8年度の表は **2026年3月分から**適用です。4月からではありません。
協会けんぽは毎年2月ごろに翌年度分を公表します。

つまり **年1回、必ず全部入れ替える作業が発生します。**
これが自前で持つことの本当のコストです。表を取り込むのは1日で終わりますが、
毎年やり続けるのは別の話です。しかも忘れても計算は完走し、それらしい数字が出ます。

APIには収録範囲を返す口を付けました。

```bash
curl "https://japan-payroll-api.tsumugi.workers.dev/v1/data-freshness"
```

各データの収録範囲と次の改定時期が返ります。**範囲の外の日付は、古い数字を返さずに断ります。**

## 自分で作る場合の出典

APIを使わない場合のために書いておきます。

| データ | 出典 |
|---|---|
| 保険料額表・等級表 | 全国健康保険協会「令和8年3月分からの保険料額表」 |
| 源泉徴収税額表 | 国税庁 源泉徴収税額表 |
| 最低賃金 | 厚生労働省 地域別最低賃金 |
| 端数処理 | 昭和22年11月14日 保険発第179号 |
| 随時改定の判定 | 昭和36年 保発第4号(**健康保険法には無い**) |

最後の1つは注意が必要です。随時改定の「2等級以上の差」という条件は
**健康保険法を最後まで読んでも出てきません。**通達にあります。
e-Gov 法令APIにも入っていません(法令ではないので)。
「法令APIに無い = 存在しない」ではない、というのがこの領域の難しさです。

## 検証のしかた

このAPIは、公表されている表と**1セルずつ突き合わせて**います。

- 協会けんぽの保険料額表と **250通り**(5都道府県 × 50等級)
- 国税庁の月額表の**公表2,079セル全部**
- 変更のたびに **4,622件** の検証を実行

式の説明から書き直したものではなく、印刷されている値との照合です。
自分で作る場合も、この形の検証は用意しておくことを勧めます。
**計算ロジックのテストは、表の取り込み間違いを一切検出しません。**

## 使う場合

無料枠は鍵もアカウントも要りません。

```bash
# AIアシスタントから(MCPサーバー・28ツール)
claude mcp add jp-payroll -- npx -y jp-payroll-mcp

# HTTP API(43エンドポイント・OpenAPI 3.0)
curl "https://japan-payroll-api.tsumugi.workers.dev/v1/payroll?prefecture=Tokyo&monthly_salary=300000&age=40"
```

1回のバッチが10人を超える場合だけ有料です(Pro 月4ドル・バッチ500人)。

- GitHub: https://github.com/kishida-devil/jp-payroll-mcp
- 退職日・年齢・随時改定まわりの罠はこちら: https://zenn.dev/kishida_devil/articles/9d5a645a105c0b

## 正直に書いておくこと

- **届出の要否を判定するものであって、届出ではありません。**
- 住民税・年末調整・国民健康保険の額は対象外です(市町村の条例で決まるものは全国一律の値が存在しません)。
- **政府機関の承認・関与・保証を受けたものではありません。**法定の届出に用いる前に出典と照合してください。

間違いを見つけたら GitHub に issue をください。条文や通達の読み違いが一番ありがたいです。
